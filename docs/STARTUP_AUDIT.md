# 🚀 Finly — Startup Audit & Product Strategy

**Date:** 2026-06-03
**Analyst:** Senior Product Strategist (AI-powered)
**Project status:** MVP (v0.1.0), labeled "учебный проект МАИ"

---

## 1. Executive Summary

**Finly** is a technically impressive PWA for personal finance management. The code quality, test coverage, and feature depth are well above what you'd expect from an "educational project." This is already closer to a **production-grade v1.0** than a typical MVP.

**The core problem:** The project is built like an engineering artifact, not a product. There's no monetization, no cloud backend, no multi-device sync, no landing page, and it's labeled as a university project. The technical foundation is strong, but the product/business layer is missing entirely.

**The opportunity:** Personal finance apps in Russia have a $50M+ TAM. Existing solutions (Дзен-мани, CoinKeeper, Дребеденьги) have weak AI features and poor offline support. Finly's AI-first approach + offline capability + PWA distribution is a genuine differentiator.

**The primary recommendation:** Stop treating this as an educational project. Build a backend (Supabase/Firebase), add multi-device sync, create a landing page, add a freemium model, and launch to real users within 4-6 weeks. The technical debt is remarkably low — most work needed is on the product/commercial side.

## 2. Что это за продукт

**Finly** — это Progressive Web Application (PWA) для управления личными финансами с AI-ассистентом и полной офлайн-поддержкой.

**Основные модули:**
- 📊 **Трекинг доходов/расходов** — ручной ввод, голос, AI-парсинг, сканирование чеков (QR/OCR/AI)
- 📈 **Аналитика** — круговые диаграммы, тренды, прогнозы, MoM-сравнение, аномалии, паттерны
- 🎯 **Бюджеты и цели** — лимиты по категориям, финансовые цели с отслеживанием
- 🔄 **Повторяющиеся платежи** — шаблоны с авто-созданием транзакций
- 🤖 **AI-ассистент** — чат с финансовым советником (online + offline), автокатегоризация
- 🔒 **Безопасность** — биометрическая аутентификация (WebAuthn), локальное хранение данных

**Техническая архитектура:**
- **Offline-first PWA** — все данные в IndexedDB, работает без интернета
- **Полностью клиентский** — единственный backend: Vercel Function для AI-прокси
- **Локальный ML** — TensorFlow.js для автокатегоризации
- **Ручная разбивка чанков** — агрессивная оптимизация бандла

## 3. Для кого он

**Primary ICP (идеальный пользователь):**
- Россияне 22–40 лет
- Доход 60 000–200 000 ₽/мес
- Технически грамотные (умеют установить PWA)
- Хотят контролировать расходы, но не любят сложные финансовые инструменты
- Ценят privacy (данные на устройстве) и offline-доступ

**Secondary:**
- Фрилансеры и самозанятые (нужен учёт доходов/расходов для налогов)
- Студенты (бюджетирование, контроль трат)
- Молодые семьи (совместное планирование бюджета — hypothesis, пока нет multi-user)

**Кто НЕ является пользователем:**
- Бизнес / компании (нет multi-user, нет счетов, нет интеграций с банками)
- Пенсионеры (сложный UI для этой аудитории)
- Люди, которым нужна автоматическая банковская синхронизация (пока нет)

## 4. Главная ценность

**Core value proposition:**
> "Умное управление личными финансами, которое работает даже без интернета и не отправляет твои данные в облако."

**3 столпа ценности:**
1. **AI-first опыт** — автокатегоризация, парсинг естественного языка, чат-ассистент, сканирование чеков
2. **Privacy + Offline** — все данные на устройстве, полная функциональность без интернета
3. **PWA-дистрибуция** — не нужно качать из App Store/Google Play, работает на всех платформах

## 5. Сильные стороны проекта

| Сильная сторона | Почему это важно для стартапа |
|---|---|
| **Качество кода** | 345+ тестов, TypeScript strict mode, чистая архитектура — можно быстро итерировать без страха сломать |
| **AI/ML глубина** | 5-уровневый пайплайн категоризации, свой ML на TF.js, intent-роутер на 15+ интентов — настоящий AI, а не маркетинговая обёртка |
| **Offline-first** | Огромное преимущество для России (метро, дачи, путешествия). Конкуренты часто требуют постоянного интернета |
| **PWA-дистрибуция** | Обход 30% комиссии App Store/Google Play. Быстрый онбординг (нет установки из стора) |
| **Техническая документация** | README на 500+ строк, ARCHITECTURE.md, DATABASE_SCHEMA.md — снижает стоимость онбординга новых разработчиков |
| **CI/CD зрелость** | Три воркфлоу GitHub Actions, Quality Gates, Lighthouse — production-grade |
| **Отсутствие реального бэкенда** | Снижает инфраструктурные риски и затраты на старте. Можно быстро запустить MVP |

## 6. Главные риски и слабые места

| # | Риск | Severity | Обоснование |
|---|---|---|---|
| 1 | **Нет облачной синхронизации** | 🔴 Critical | Данные теряются при смене устройства или очистке браузера. Без синхронизации продукт не воспринимается всерьёз |
| 2 | **Нет монетизации** | 🔴 Critical | Продукт бесплатный и нет плана, как зарабатывать |
| 3 | **Нет landing page** | 🔴 Critical | Невозможно привлекать пользователей — непонятно, что за продукт, зачем он нужен, как начать |
| 4 | **Локальная аутентификация** | 🟡 High | Нет реального аккаунта — пользователь не может восстановить доступ. Данные привязаны к устройству |
| 5 | **Отсутствие метрик и аналитики** | 🟡 High | Нет данных о том, как пользователи используют продукт, что работает, что нет |
| 6 | **IndexedDB — единственное хранилище** | 🟡 High | При росте данных (>5000 транзакций) производительность деградирует. Браузер может удалить данные |
| 7 | **Нет мультивалютности** | 🟡 High | Заявлена в планах, но не реализована. Критично для пользователей с валютными доходами/расходами |
| 8 | **Зависимость от OpenRouter** | 🟡 Medium | AI-чат зависит от стороннего API. При проблемах с OpenRouter теряется ключевая фича |
| 9 | **Ручной ввод данных** | 🟡 Medium | Без банковской интеграции пользователь должен вводить всё вручную — высокий порог входа |
| 10 | **Нет onboarding-туториала в приложении** | 🟢 Low | Онбординг из 3 слайдов слишком поверхностный. Пользователь не понимает, с чего начать |

## 10. Варианты монетизации

| Модель | Плюсы | Минусы | Recommendation |

### Early adopters:
- Технические специалисты (разработчики, дизайнеры, продакт-менеджеры)
- Активные пользователи Telegram-каналов о финансах и личной эффективности
- Студенты технических специальностей

### Где искать первых пользователей:
1. **Telegram-каналы:** @rational_answer, @kikfinance, @finhealth, @dohodchiki
2. **Product Hunt** — запуск с английским переводом интерфейса
3. **Хабрахабр / VC.ru** — статья о технической реализации (архитектура, AI/ML)
4. **YouTube** — обзор приложения от финтех-блогеров
5. **Личные контакты** — первые 50 пользователей через прямой контакт

### Какой use case продавать первым:
**"Узнай, сколько ты реально тратишь на кофе/такси/доставку"** — самый простой и понятный вход. Неделя использования → инсайт → мотивация продолжать.

### Какой pain point использовать в messaging:
**"Ты не знаешь, куда уходят деньги. Банковское приложение показывает только общую сумму. Finly покажет конкретные категории и поможет сократить ненужное."**

### Что показать в demo:
1. Быстрый ввод через AI: "кофе 450 рублей в Старбаксе" → авто-категоризация
2. Дашборд: баланс, доходы, расходы, свободные деньги
3. Аналитика: категории за месяц (круговая диаграмма), сравнение с прошлым месяцем
4. AI-ассистент: вопрос "на чём я могу сэкономить?" → ответ на основе реальных данных

### Метрики, которые важно собирать уже сейчас:
- **Активация:** % пользователей, добавивших ≥5 транзакций за первую неделю
- **Retention:** Day 1, Day 7, Day 30
- **Core action frequency:** транзакций в день на активного пользователя
- **Feature adoption:** % использующих AI-ввод, сканер чеков, бюджеты, цели
- **NPS или CSAT:** опрос после 2 недель использования

### Гипотезы для валидации до масштабирования:
1. Пользователи готовы платить 299 ₽/мес за AI-ассистента
2. Offline-режим является решающим фактором для ≥20% пользователей
3. PWA-дистрибуция не снижает конверсию в установку по сравнению с нативным приложением
4. Пользователи с ≥3 бюджетами имеют retention в 2× выше
5. AI-парсинг естественного языка используют ≥50% активных пользователей

## 15. Questions I Need Answered to Make the Strategy Sharper

1. **Кто целевой пользователь?** Ты делал проект для конкретной аудитории или "для всех"? Есть ли уже реальные пользователи? Сколько?

2. **Планируется ли коммерциализация?** Сейчас проект — учебный. Ты рассматриваешь его как потенциальный стартап или это остаётся академическим проектом?

3. **Есть ли бюджет на развитие?** Готов ли ты платить за Supabase ($25/мес), OpenRouter API, Vercel Pro, домен, почтовый сервис?

4. **Кто в команде?** Ты один или есть другие разработчики/дизайнеры/маркетологи? Это определяет скорость и реалистичность roadmap.

5. **Почему PWA, а не нативное приложение?** Это осознанная стратегия (экономия на разработке, лёгкая дистрибуция) или временное решение? Это влияет на GTM.

6. **Планируется ли банковская интеграция?** Это ключевой фактор positioning: "privacy-first без доступа к счетам" vs "удобная синхронизация с банками".

7. **Есть ли у тебя опыт в финтехе или личных финансах?** Или проект делается "для себя"?

8. **Какие конкуренты тебе нравятся/не нравятся и почему?** Это поможет точнее определить positioning и differentiation.

9. **Готов ли ты сейчас показывать продукт реальным пользователям?** Или хочешь сначала "допилить"?

10. **Кто будет заниматься маркетингом и продажами?** Технический продукт без дистрибуции не растёт.
