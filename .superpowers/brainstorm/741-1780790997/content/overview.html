Выбери приоритеты для доработки (можно несколько)

Высокий приоритет Средний Низкий
Баг
CI-диапазон невидим на графике
Прогноз расходов должен показывать закрашенную зону доверительного интервала (±CI), но stroke="transparent" делает её невидимой. Ключевая фича прогнозирования не работает визуально.
Баг
Доход захардкожен: 100 000 ₽
В PredictiveTab.tsx WhatIfSimulator получает totalIncome={100000} вместо реального дохода пользователя. Все расчёты нормы сбережений в симуляторе — неверные.
UX-полировка
CalendarHeatmap: зелёный = больше трат?
Сейчас больше расходов = темнее зелёный. Но зелёный — цвет «хорошо». Правильная семантика: больше трат → тёплый цвет (янтарный/красный). Показать сравнение.
Не хватает
CalendarHeatmap без меток месяцев
GitHub-style heatmap без меток месяцев сверху — пользователь не понимает, где январь, где июнь. Нужна строка с 12 метками месяцев над колонками.
Не хватает
AI-ответы без markdown-рендеринга
Спека требует «markdown rendering», но AI-ответы выводятся как whitespace-pre-line простым текстом. Заголовки, списки, bold — всё слипается в одну кашу.
UX-полировка
AI-чат без пресетов вопросов
Пустое поле ввода создаёт blank page problem — пользователь не знает что спросить. Пресеты-пилюли: «Где я трачу больше всего?», «На чём сэкономить?», «Прогноз на месяц».
UX-полировка
WhatIf: нативный range вместо Radix Slider
@radix-ui/react-slider уже установлен, но используется нативный <input range>. Radix даёт лучший тактильный отклик, доступность, стилизацию. Слайдеры — центральный UI симулятора.
Код
isOnline не реактивный
navigator.onLine вычисляется один раз при рендере. Если пользователь отключился после загрузки страницы — UI не обновится. Нужен useEffect с событиями online/offline.
Код
useState<any> в PredictiveTab
Три state-поля типизированы как any. TypeScript теряет проверку типов для всего прогнозного кода. Легко фиксится — типы уже есть в db/premium.ts.
